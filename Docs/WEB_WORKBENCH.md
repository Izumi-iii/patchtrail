## 3. 当前实现结构

```text
app.py                           本地启动器
src/patchtrail/web/
├── server.py                    HTTP 适配、同源限制、静态资源白名单
├── service.py                   字段校验、请求去重、会话并发互斥、Git 检查
├── store.py                     SQLite 会话/消息/提交记录
└── static/
    ├── index.html               对话界面与原生 dialog
    ├── app.js                   请求、会话选择、草稿、状态与错误处理
    ├── styles.css               基础布局、手机侧栏、减少动画设置

tests/
├── test_web.py                  标准库 unittest 与 HTTP 集成测试
```

Python 标准库 HTTP 服务用于本地开发原型，不作为最终公网服务方案。以后替换 FastAPI 等传输层时，保留服务与持久化边界，并在接入真正任务模型时进行明确数据迁移。

## 4. 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/healthz` | 明确返回当前能力和未接入状态 |
| GET / POST | `/api/conversations` | 列表 / 新建 |
| GET | `/api/conversations/{id}` | 会话详情与消息 |
| PATCH | `/api/conversations/{id}` | 修改 title 或 repository_path |
| DELETE | `/api/conversations/{id}` | 删除会话并级联删除消息和去重记录 |
| POST | `/api/conversations/{id}/messages` | 提交需求，包含 content、mode、request_id |

写请求要求 JSON 和 `X-PatchTrail: 1`，校验 Host/Origin，不开放跨域。正文上限 64 KiB，任务文本上限 12,000 字符。所有用户文本和 Git 元数据在页面使用 textContent，不作为 HTML 执行。

同会话的发送、修改和删除互斥；另一会话可正常操作。消息对和提交标识在一个数据库事务内保存。并发忙时返回 409，不重复执行同会话操作。

前端会中止过期的详情读取，并以请求版本及缓存版本阻止晚到结果覆盖。发送回复绑定原会话 ID；切换后不更新新会话的输入与消息。响应丢失后，在同一页面重试相同内容会复用 request_id。刷新前尚未提交的草稿和正在等待的请求不是持久化任务，不承诺跨刷新恢复。

## 5. 本地边界

- 只绑定回环地址，不注册外部站点，不接收远程 Webhook。
- Git 使用参数数组及超时，禁用 fsmonitor 和可选锁；不会调用项目脚本、测试、依赖安装或 shell。
- 只接受绝对仓库根路径，不在网页暴露任意文件下载接口。
- 无自动提交、推送、删除或清理仓库行为。
- 当前 Git 检查读取工作区，并非对某个固定 commit 的不可变源码分析；后续修复阶段必须使用设计中的基准快照。
- SQLite 和导出 JSON 可能包含本机路径和任务描述，不把运行目录提交到 Git。
- 该预览是单机单服务实例；不提供账号隔离、多租户认证或强对抗执行保证。

## 6. 测试与手工检查

标准库测试覆盖持久化重开、去重冲突、字段校验、会话隔离与删除、忙状态、真实 Git 读取和原始仓库不变、非法路径、HTTP 资源边界及跨站拒绝。

浏览器测试覆盖首次打开、中文输入法与换行、纯文本展示、刷新、重命名、对话框 Escape 与焦点恢复、仓库成功/失败、会话切换竞态、后台回复隔离、错误输入恢复、丢失响应重试、导出、搜索、删除确认、手机侧栏及无横向溢出。

手工体验：

1. `python app.py`，打开终端显示的本地地址。
2. 「记录需求」发送复现步骤，刷新确认仍存在。
3. 关联本地仓库，切换到「仓库检查」，发送请求，核对 HEAD 和 Git 工作区提示。
4. 用不存在的目录再次检查，确认显示失败且可修改路径继续。
5. 新建另一个会话，确认原会话内容与仓库不串入新会话。

测试完成数量以当次测试输出为准；浏览器截图与结果位于 `.test-artifacts/webui/`，该目录不进入版本控制。
