# DeepSeek：结构化编辑与手写补丁的单轮对照

日期：2026-10-17。旧协议为模型手写 Git diff，新协议为 exact_replace_v1：模型提交精确文本替换，工具生成累计补丁。本轮真实评估沿用用户已确认的预算，没有人工修正候选，也没有在运行中调整提示或实现。

## 结果

两版本各执行一次同样的 7 个公开小型修复任务和 1 个错误基准对照。新旧版本均为 **7/7 修复任务通过最终独立验收，1/1 对照在零模型调用下正确拒绝**。

| 指标 | 旧：手写 diff | 新：结构化编辑 | 本轮观察 |
| --- | --- | --- | --- |
| 模型请求 | 28 | 21 | 减少 25.0% |
| 工具调用 | 30 | 23 | 减少 7 次 |
| 编辑工具错误 | 7 | 0 | 新协议未发生编辑错误 |
| 输入 token | 47,189 | 35,940 | 包含提供商计入的缓存输入 |
| 输出 token | 3,696 | 2,451 | 以返回的 usage 为准 |
| 总 token | 50,885 | 38,391 | 减少 12,494，约 24.6% |
| 进入验证的候选 | 7 | 7 | 两轮均每任务 1 个候选 |
| 第二候选后修复成功 | 0 | 0 | 均未触发候选测试失败后的再修复 |
| 案例耗时合计 | 273.984 秒 | 269.077 秒 | 包含准备、模型和容器执行 |
| 8 案例中位耗时 | 36.039 秒 | 36.2655 秒 | 没有观察到明确的中位耗时改善 |
| 费用 | unknown | unknown | 未核对账单或价格，不把 token 降幅当作费用降幅 |

新协议 7 个修复任务均为 3 次模型请求：读取、编辑、提交。工具调用数可以超过模型请求数，因为一个模型响应可包含多个读取工具调用。两轮 usage 均完整，没有缺失请求使用量或未核算调用额度。

旧协议的 7 次错误全部为 propose_patch / patch_does_not_apply，出现在去重、布尔解析和缓存任务。新协议这三个任务没有出现匹配、哈希、补丁重放或其他工具错误。

**总 token 减少并不表示每个任务都更省。** 原本没有格式错误的 4 个任务，结构化版本的 token 均增加；新工具字段、哈希和提示存在交互开销。本轮整体节省集中在旧版需要多轮纠正补丁格式的 3 个任务。

新版本最终补丁经阅读核对仍满足原需求：去重使用集合记录并保留顺序；布尔文本处理规范化、真假值和 ValueError；跨文件任务同时修改 helper 与调用方；缓存按键是否存在判断命中。average-empty 用 len 检查空列表，未再复制整个输入列表。语义与格式细节也存在差异，不能把所有 token 差异单独归因于字段数量。

## 可比条件及限制

- 8 个任务的 ID、顺序、基准提交及原始数据 SHA-256 一致。
- 数据集：patchtrail-python-v1；SHA-256：`bbda61692b0d259f95b748604d8a18fe970a951506d949bde42542ee6a62035f`。
- 模型配置一致：deepseek-flash，https://api.deepseek.com，关闭思考模式；每次输出最多 4096 token、超时 60 秒、传输自动重试为 0。未记录提供商内部模型版本。
- 同样每任务最多 8 次模型请求、2 个候选，实验总上限 48 次。新轮实际使用 21 次，剩余额度未继续使用。
- Python 与框架依赖版本一致；实际镜像 ID 均为 `sha256:430a1d9d69c9b4def247505fef9b5e4137fac95ac843ace6e5bff6729cec8179`。
- 实现变化为 agents/runner.py、tools/code.py、新增 tools/editing.py，以及 workspace/snapshot.py。提示、工具 schema、读取结果的换行信息和 Git 换行隔离同时变化。

这是两版本各一次的同任务观察，不是随机化实验或多次重复统计。仅 7 个公开、自编小任务，不能推断企业仓库修复成功率或稳定的 25% 请求节省。新版本同时更改编辑协议和 Git 配置隔离，没有拆开各因素做消融。端到端时间受 Docker 和机器负载影响，本轮不声称整体明显加速。

两轮都没有已提交候选测试失败后的重试。因此本轮支持“当前任务上工具生成补丁可消除观察到的格式纠错回合”，不支持“测试驱动自纠错效果已得到真实模型验证”。此前脚本模型的错误候选重试证据仍独立记录。

## 环境恢复与证据审计

本轮开始前 WSL/Docker 曾超时，并观察到 Windows 内存不足；前置容器检查以 ENVIRONMENT_ERROR 结束，模型请求数为 0。这些环境失败没有并入模型能力分数。用户重启服务后，WSL 查询恢复，启动 Docker，再用跨文件任务完成真实容器预检；随后才开始本轮唯一一次付费模型实验。

本轮没有修改实现文件；结束后核对实现身份仍与启动记录相同。重新审计新旧两轮 Agent/独立验证的 **2,101 个 manifest 文件条目**，均一致；核对全部样例未被改变、7 个最终候选通过独立保留验收，模型会话中没有 corrected.patch 或 holdout_dir 字段。对新轮 **1,428 个文件**扫描本机密钥值，未发现泄露。结束时没有遗留带 PatchTrail 标签的容器。
